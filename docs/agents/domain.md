# Domain docs

This repo uses a single-context layout:
- `CONTEXT.md` at the repo root.
- Architecture decision records in `docs/adr/`.

Before exploring, read CONTEXT.md and ADRs relevant to the work.
If absent, proceed silently; domain-modeling creates them when
terms or decisions are resolved.

Use the glossary's terminology consistently. Note real vocabulary
gaps for domain-modeling.

Explicitly flag proposals that contradict an existing ADR.
